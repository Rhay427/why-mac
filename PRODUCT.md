# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML and CSS prepared for Cloudflare Pages. No framework, build system, runtime dependency, backend, analytics, or form is required for this release surface.

## Users

Mac users who want a clear, immediate explanation when their Mac feels hot, slow, busy, battery-hungry, or unwilling to sleep automatically.

## Product Purpose

Why? is a native macOS menu-bar utility that turns supported system signals into a concise plain-English explanation. The website introduces that utility accurately and gives visitors a clear path toward the future direct-download release.

## Positioning

Why? runs a manual, approximately five-second check only when the user asks. It correlates supported macOS signals into one primary explanation rather than continuously monitoring the Mac or presenting a dashboard of raw telemetry.

## Operating Context

The app lives in the macOS menu bar. A user opens it, starts a check, waits approximately five seconds, and receives a conclusion-first explanation with optional supporting contributors and sleep context.

## Capabilities and Constraints

- Native macOS application targeting macOS 13 Ventura or later.
- Apple Silicon-first V1.
- Manual checks only; no continuous monitoring.
- On-device diagnosis with no user account.
- Supported V1 signals include thermal state, memory pressure, sustained CPU/application activity, battery-use contribution, and automatic idle-sleep assertions.
- Direct distribution is planned, but a signed and notarized public DMG is not available yet.
- Open-source preparation uses the MIT license. No purchase, account, or license key is required to build or use the source.
- Public source repository: https://github.com/Rhay427/why-mac. The website download control remains visibly unavailable until the official download is ready.
- No personal name or developer attribution appears on the website.

## Brand Commitments

- Product name: Why?
- Product line: Your Mac, explained.
- Preserve the existing dark navy, deep blue, crisp white, and quiet cool-gray palette established by the approved catalog artwork.
- Use the existing Why? icon and real product interface imagery.
- Voice is plain, calm, conservative, and specific. Avoid hype and unsupported claims.

## Product Principles

- Explain before exposing detail.
- State only what the collected evidence supports.
- Keep checks manual and user initiated.
- Prefer one useful conclusion over a diagnostic dashboard.
- Earn trust through restraint, privacy, and native macOS behavior.

## Accessibility & Inclusion

The marketing surface must remain keyboard accessible, readable at increased text sizes, responsive on mobile and desktop, and respectful of reduced-motion preferences.
